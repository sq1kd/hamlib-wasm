<CardGrid>
  <Card title="Same backends as rigctl" icon="approve-check">
    The rig backends are the pinned upstream Hamlib release, compiled with
    Emscripten, not a port. A model behaves the way `rigctl` drives it.
  </Card>
  <Card title="One rig object, or every Hamlib call" icon="puzzle">
    Start with state snapshots, events and plain booleans. When you need split,
    memories or antennas, `rig.raw` has a typed method per Hamlib call, on the
    same connection.
  </Card>
  <Card title="Browser, Node and Electron" icon="laptop">
    Web Serial in desktop Chrome, Edge and Firefox 151+; the `serialport`
    package in Node and an Electron main process. One API in all three.
  </Card>
  <Card title="React hooks" icon="seti:react">
    A provider and hooks that own the module, the rig and the polling, and
    survive StrictMode double mounts and unmounts mid-call.
  </Card>
</CardGrid>
